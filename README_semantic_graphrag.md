# 多关系 GraphRAG

已接入 `rag.py` 的知识库 / GraphRAG 模式；自动模式识别到图中实体及关系类问题时也进入这条流程。检索发生在回答生成之前，路径完整进入 Evidence Guard，通过的证据才能进入生成上下文。界面和聊天导出保留逐边引文、来源、路径、证据编号及实际使用状态。快速模式沿用项目原有的“跳过独立审核”行为。

图存储为 `semantic_graph/medical_graph.sqlite`，是从本地数据构建的**独立 SQLite 属性图**，不代表在线 Neo4j 已增加这些关系。不是向量相似度检索；`entities`、`edges`、`sources` 表支持按端点、关系类型和来源记录独立遍历。原 Neo4j 和 Chroma 继续参与联合检索。

## 关系语义

| 关系 | 实体 | 来源与边界 |
|---|---|---|
| HAS_SYMPTOM | 疾病 → 症状 | medical.json 的 symptom 列表；不能据此确诊 |
| HAS_INGREDIENT | 药品 → 成分 | composition 原文中保守解析的名称；不从药名猜成分，不合并盐型 |
| CLASS_MEMBERSHIP_ASSERTION | 药品 → 药物类别 | 只接纳同一产品原文中“本品为 / 是 / 属于某类”的明确肯定句；类别提及、否定、对比不建立归属 |
| INDICATION_MENTION | 药品 → 疾病 | 现有候选 CSV 经药品、记录、章节、引文和偏移核对；只是用途章节提及 |
| CONTRAINDICATION_MENTION | 药品 → 疾病 / 症状 / 人群 / 原文条件 | 禁忌章节字面提及；禁用、慎用、条件由原文决定 |
| CAUTION_MENTION | 药品 → 疾病 / 症状 / 人群 | 注意事项章节字面提及 |
| INTERACTION_MENTION | 药品 → 成分 / 药品 | 相互作用章节的名称提及；保留否定、不确定性和剂量条件，不自动定级 |
| ADVERSE_REACTION_MENTION | 药品 → 疾病 / 症状 / 人群 | 不良反应章节字面提及，不推导因果 |

当前输入均未完成官方或临床核验。中文词典匹配和成分解析也会遗漏或误解实体；这些边是可追溯的来源关系，不能声称为已经核验的完整医学知识图谱。复杂成分句、未识别名称和长篇章节会明确遗漏。原文里的中药组合名称不自行拆开；疑似类别名不用于自动归类。

## 查询与约束

- 查询规划识别实体全名、通用名、来源目录中的别名和口语意图，并进行最多 5 跳的关系检索。省略盐型或剂型时只扩展搜索候选，不建立医学等价关系；歧义名称不强行连边。
- 正反向遍历使用实际关系端点，并保留原始陈述方向。指定多个实体时，每个输出路径必须包含全部已识别实体。达到预算时明确标记结果不完整。
- 双药相互作用必须有实际相互作用提及边，并通过明确成分原文或直接药品名称连接。`A → 提及 C ← B` 不支持 A/B 相互作用；共享疾病也不是两药相互作用的桥梁。
- 同一药品节点使用的各条边须来自同一来源记录；不会把不同版本说明书上的成分和禁忌拼成一个证明。
- 一个多跳路径作为一个完整引用单元，编号不会因补检或界面展示而拆散。图路径与直接原文分别保留名额，普通原文按检索通道轮流选取。证据不足时可继续追加最多 3 条原文补检证据，并保留全部原有路径及编号。
- 整体输入文件 SHA256、构建策略摘要、索引 SHA256、原始行字节位置与 SHA256、章节文本摘要、引文及提及位置共同核验。数据或构建策略变动后旧索引停止提供证据，需重建。索引与清单是本地完整性检查，不是第三方数字签名。
- 未连通、未覆盖的关系、节点扇出截断和预算耗尽会写入 trace；未命中不表示没有相互作用或可以安全合用。
- 现有 `drug_categories_western.json` 等未经核验的类别表不用于推出类别归属或药物风险；需要正式审核的分类关系才能扩展这部分推理。

例如在当前语料中，可以查询阿司匹林肠溶片与布洛芬片，经布洛芬片的成分原文连接到阿司匹林肠溶片相互作用章节中的布洛芬提及。症状 → 疾病 ← 用途提及药品 → 成分等路径也能遍历，但不能把它解释为症状诊断或个体治疗推荐。

## 使用

在 `RAG_project/data` 目录执行（只需要 Python 标准库，构建和查询不调用云端）：

```powershell
python medical_semantic_graph_cli.py build
python medical_semantic_graph_cli.py query "阿司匹林肠溶片与布洛芬片的成分和相互作用"
python medical_semantic_graph_cli.py query "哮喘患者使用布洛芬片有什么禁忌？"
python medical_semantic_graph_cli.py query "胸痛相关疾病有哪些症状和相关药品成分、禁忌？"
python -m unittest test_medical_semantic_graph -v
```

构建读取：

- `kg_output_clean_v2/drugs.jsonl`
- `kg_output_clean_v2/source_records.jsonl`
- `kg_output_clean_v2/sections.jsonl`
- `kg_output_clean_v2/disease_candidates_full.csv`
- `data/raw/drug_db/MedGraphRAG-Drug-DB/medical.json`

生成 `semantic_graph/medical_graph.sqlite` 和 `.manifest.json`；均为可重建派生产物。更新入库数据后，应先更新图谱导出快照，再重建本索引；不会自动把在线 Neo4j 的变化同步到本地快照。

开关 `MEDICAL_SEMANTIC_GRAPH_ENABLED=0` 可关闭新通道。`MEDICAL_SEMANTIC_GRAPH_INDEX` 可指定派生索引路径。缺少或过期索引时，图通道报告原因，其他检索通道继续工作。

## 验证范围

`test_medical_semantic_graph.py` 覆盖异构四跳、双药成分连接、第三药伪桥接拒绝、无连接实体、不合并盐型、跨记录拒绝、源文件 / 索引篡改、否定与后续不确定句、遍历预算、原文短字段引用、界面转义与导出引用绑定。

后端集成测试执行真实 `RagService._stream_agent`、Evidence Guard、引用构建和自动路由分支，替换外部数据库服务与模型为离线桩，同时验证 strict / fast 两种模式。测试不验证云端模型的最终临床表述；真实回答仍须以逐边原文与来源状态为准。

## 图路径显示与成分字段修复

前端使用 `medical_semantic_graph_view.py` 绘制实体卡片和带关系标签的方向箭头。反向遍历仍显示真实陈述方向；窄屏横向滚动，逐边原文与来源折叠查看。路径卡片显示其证据编号、进入上下文 / 回答引用状态，不在原文章节列表重复堆叠路径文本。历史消息中的图路径也可按新样式展示。

旧 P3-07.2 全库相互作用来源检索保留，默认折叠为“补充来源线索”。它可能包含其他剂型，只供进一步查阅，不等同于当前回答引用的图路径，也不自动确认药物组合风险。

Evidence Guard 允许已核对结构化边中的完整成分实体名作短引文。若审核漏掉单一制剂的成分字段，程序仅对来自同一记录、没有冲突、可逐字核对的完整成分原文恢复字段描述；不会借此放行相互作用、安全性、治疗或剂量问题。已用出现误拒的实际聊天保存证据离线回放验证，未改写旧聊天答案或历史记录。

本次构建：35,307 个实体、294,470 条来源关系边、110,019 个来源章节 / 症状字段，其中只有16条满足保守解析规则的明确类别归属。具体输入摘要、分关系数量和解析遗漏数见 `semantic_graph/medical_graph.manifest.json`。加入双疾病药品集合检索后，运行 29 项新测试及 87 项已有相互作用测试，共 116 项通过。早期7个语料查询保存在 `semantic_graph/smoke_queries.json`；最新双疾病复测见 `semantic_graph/disease_pair_smoke.json`。未取得此策略允许的连通路径表示当前证据链覆盖不足，不能推论某组合安全。

## 双疾病相关药品相互作用检索

支持“糖尿病用的药跟过敏性鼻炎用的药有药物相互作用吗？”以及“治某病的药 / 某病用药”等自然表达。`medical_disease_pair_retrieval.py` 分别建立两组候选制剂，再按具体制剂名称、明确成分或同来源明确类别归属连接；每条路径必须包含两个疾病端点、两种不同制剂和恰好一条相互作用提及边。

候选准入依赖同一来源用途章节的直接用途措辞或独立列举的适应症条目，仍不代表医学上已确认的治疗关系。背景风险、排除继发病因、并发症和神经痛等语境被保守排除；含糊文字宁可遗漏。类别词表仅是可识别的原文字面术语，不是自动分类表，也不会把“糖皮质激素”和“糖皮质类固醇”未经核验就连为同义节点。

禁止通过第三种药物的共同提及、共同疾病、同名不同来源记录来完成连接。类别或成分桥接缺失时保留缺口，支持输出具体缺少什么，而不是笼统拒答。界面展示两组实际检索数量、背景记录排除数、逐边原文和未取得的类别连接。`coverage_complete` 始终为 false；`searched_snapshot_exhausted` 仅说明有没有穷尽本次本地快照中的合格候选，不代表完整医学覆盖。

复测原问题：糖尿病用途提及138种制剂中，72种通过当前保守语境筛选，66条背景 / 含糊记录被排除；过敏性鼻炎119种中，100种通过，19条被排除。本次输出6条四跳路径，包含格列吡嗪制剂、盐酸西替利嗪滴剂及具体胰岛素制剂、丙酸倍氯米松气雾剂等来源记载示例。没有把气雾剂的相互作用原文转移到“相互作用尚不明确”的鼻喷雾剂。

这些是第三方原文的检索结果，不是个体用药建议。通过真实来源核验与严格模式引文校验，并完成后端 strict / fast 离线模型桩集成测试；未调用云端模型验证其最终临床措辞，也未更改用户旧聊天答案。

## 患者口语、药名候选与意图识别

`medical_query_understanding.py` 从经索引来源校验的药品目录识别通用名、制剂名和原有别名，如“二甲双胍”“扑尔敏”。剂型后缀与有限盐型前缀只用于生成搜索候选，不能据此认定具体产品相同。普通片、缓释片与复方产品保留区别；“吃了 / 服用”会排除候选中的针剂、外用剂型，仍不会擅自确定普通片或缓释片。

“会有问题吗 / 会不会有事 / 能一块吃吗 / 相克吗”可进入相互作用检索。“怎么吃 / 一天几次”进入用法用量原文章节检索；“吃了以后头晕 / 拉肚子”识别为不良反应相关诉求，不能据此确认因果。“喂奶 / 怀孕 / 肾不好 / 拉肚子”等可提供哺乳、妊娠、肾功能、腹泻的检索词，但不会被改写成患者诊断或图谱事实。

“降糖药 / 胃药”等成分未明确的称呼、存在冲突的商品名、未识别的药名，先询问药盒名称或成分。明确用药语句中的单字差异可给出候选提示，如“阿莫西琳”提示核对“阿莫西林”；不会自动替换并据此回答用药风险。暂不覆盖所有商品名、拼音、语音错词或跨轮指代。

`medical_patient_pair_retrieval.py` 将两组候选具体制剂通过原文成分 / 类别与相互作用提及连接。患者提到的糖尿病等背景疾病不再挤掉两种药的检索锚点；明确询问疾病 / 症状相关药品时仍保留原探索路线。同一相互作用原文连接多个候选剂型时不重复计作独立发现。Evidence Guard 可放行有依据的来源描述，同时保留“实际产品、剂量和患者能否安全合用”的未知部分。

原失败问题“糖尿病患者正在吃二甲双胍，又因为胃不舒服吃了西咪替丁，会有问题吗？”已在真实本地语料中检出 3 条不同相互作用原文路径，包含 AUC 增加、肾脏清除率等原文。严格引文审核的离线模型桩回放得到 partial：可描述原文，不能确认该患者安全合用。10 个真实语料查询及逐边证据保存于 `semantic_graph/patient_language_smoke.json`。本轮没有重建图索引或改写医学源数据。

运行 `python -m unittest discover -s . -p "test_medical*.py"` 检查口语识别、歧义澄清、候选过滤、完整图证明、证据配额、补检与后端编排，本轮共 139 项通过。外部模型及数据库在集成测试中使用离线桩；尚未进行云端模型与在线 Neo4j / Chroma 联调。
