# 图谱扩边实施顺序

## 先确定缺口

运行以下只读诊断，在修改抽取规则和重建索引前保存基线：

```powershell
python data/medical_graph_gap_diagnosis.py --cases data/evals/graph_gap_cases.json --output data/reports/graph_gap_diagnosis_20261104.json
```

也可指定单个问题：

```powershell
python data/medical_graph_gap_diagnosis.py --question "阿司匹林肠溶片与布洛芬片的成分和相互作用" --output data/reports/graph_gap_single.json
```

诊断对照原始导出文件与派生 SQLite 图，按制剂列出成分、用途、禁忌、注意事项、相互作用、不良反应和用法用量的来源情况、图边数量及原文位置。报告不会写入图边，不连接云端模型或 Chroma。

当前诊断主要覆盖已识别制剂的成分/相互作用及明确类别归属。不是全图穷尽搜索，不覆盖所有药理学章节或外部官方说明书；“独立章节缺失”不表示其他章节完全没有相关内容。例如部分禁忌和不良反应实际保存在 warnings 内，必须核对原文，不能据栏目缺失认定医学资料不存在。

## 根据分类实施

| 诊断 | 具体操作 |
| --- | --- |
| 药名或制剂未确认 | 修复识别或先澄清；不补医学关系 |
| source_missing_in_local_snapshot | 检查源文件、字段映射和导出丢失；本地确无依据时补可靠来源 |
| composition_requires_parser_review | 人工对照成分原文，确认是否超出保守解析器支持范围 |
| composition_extraction_gap_candidate | 以原文和坐标验证抽取漏项，修复规则并增加该例回归 |
| interaction_extraction_gap_candidate | 审查字面对象是否真是合用对象，保留否定/条件后补提及边 |
| existing_join_not_returned_candidate | 原图存在连接线索，检查同来源、剂型、跳数、截断及排序；不先扩边 |
| class_membership_source_review_candidate | 原文类别词可能是背景或比较，只有明确自我分类才能补类别归属 |
| graph_paths_available | 检查回答 trace 的 evidence_flow 和审核原因；不归因为图中缺关系 |
| no_pair_link_in_checked_sources | 当前范围没有连接依据，不补臆测边；补来源并说明证据范围 |

诊断分类是待核查线索。未抽取字面提及也可能是自身成分、类别子串、否定、不同剂型或背景描述，不能直接批量转边。

## 扩边的字段要求

每条新增来源关系都应保留：起点制剂、目标实体及类型、关系类型、source_record_id、section_id、来源网址、原文完整句、原文坐标、来源哈希；给药途径、剂型、剂量条件、人群、否定和不确定性必须可从同一原文回查。

优先顺序为成分完整性、原文明确的类别归属、相互作用对象与条件、禁忌/注意事项中的患者条件。新的关系类型只有在来源中能稳定抽取并逐边校验时才加入；不创建已确认风险等级或临床推荐等原文没有支持的属性。

机制证据按全库来源章节建立派生边：`MECHANISM_MENTION`、`METABOLISM_MENTION`、`ENZYME_MODULATION_MENTION`、`EXPOSURE_CHANGE_MENTION`、`TRANSPORT_MENTION`、`MECHANISM_OUTCOME_MENTION`。这些类型表示原文在对应药品章节提及相关机制术语，不代表已经核验的药代动力学事实或临床因果。每条边保留整句/分句原文及精确术语位置；机制问题触发说明书相互作用/注意事项检索和图边检索。通用术语（如“代谢”“浓度”）只用于定位原文，不可作为两种药品间的关系证明。双药机制查询按药品分别呈现来源陈述，仅当来源直接连接两药时才显示相互作用关系。

共享第三种药物不是两药相互作用证明。普通类别提及不是类别归属，另一制剂的类别归属也不是当前制剂归属。原文技术核验不等于临床验证。

## 验收再接入

先在独立派生索引验证抽取改动，保留现有来源和主索引作为基线。每个修复都增加一个原文正例，以及否定、条件、相近药名/其他剂型、共享第三药等反例。

比较修复前后的实体解析率、来源字段覆盖、可逐边核验路径、错误连接、最终逐项引用和 P50/P95 检索耗时。先用本地回归验证结构与来源，再在实际运行环境验证 Chroma、审核与回答；不能用图边数量上涨替代质量验收。

当前四例基线见 `data/reports/graph_gap_diagnosis_20261104.md`；其 JSON 文件包含来源证据。建议在该用例集加入更多去标识化的真实失败问题，以错误类型频次确定下一批修复。
