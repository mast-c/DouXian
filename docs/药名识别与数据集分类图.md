# 药名识别与数据集分类图

## 识别与意图区分

原实现对药名左右中文字符采用前后词白名单。完整药名后接“属于”或未列出的自然表达时，也可能被排除；后续未知制剂检查因此错误地要求澄清。

现在先用本地药品目录最长匹配识别完整制剂名。完整药名的后续普通叙述不再依赖问题词白名单；未知前缀、盐型延长、剂型延长、加强版等继续检查，避免把“未知甲药片”当作“甲药片”。简称、盐型候选、歧义别名和错别字沿用单独的保守处理，不自动替换患者产品。

分类意图与药名识别分离；“属于什么类”“是什么类别”“算不算抗生素”“是不是抗生素”“是中药还是西药”属于分类查询。仍有规则局限，尚不是自由语言模型的完整语义理解；增加陌生表达时先测实体识别、再测意图，避免重复用前后词限制已知实体。

## 分类图

来源为 `data/data/raw/drug_db/MedGraphRAG-Drug-DB/drug_categories_western.json` 和 `drug_categories_chinese.json`。旧实现没有导入它们；原有 DrugClass 与 CLASS_MEMBERSHIP_ASSERTION 只来自药品章节明确自我分类。

新增可独立遍历的派生 SQLite 图：`data/semantic_graph/dataset_categories.sqlite`，附带 `.manifest.json`。不修改主医疗图或 Neo4j，不需要重新入库。首次分类检索构建，随后复用；输入文件哈希、药品目录或构建代码变化会重建该派生索引。

实体与关系：

- 与本地药品目录全名精确一致的条目，复用 Drug 的 ID。
- 未匹配条目保留为 CatalogDrug 目录实体，不自动匹配其他剂型；纯分类问题可按目录全名查询它们，但不得把目录条目当作已经确认的患者产品，也不用于临床问题的药名补全。
- DatasetCategory 保存带来源文件和上下级路径身份的分类节点，不与药理 DrugClass 合并。
- Drug/CatalogDrug → DATASET_CATEGORY_MEMBERSHIP → 二级 DatasetCategory。
- 二级 DatasetCategory → DATASET_CATEGORY_PARENT → 一级 DatasetCategory。

每条分类边保留来源文件 SHA256、JSON Pointer。查询时重新验证数组元素和上下级键关系，不能用生成的文字代替 JSON 结构证明。前端显示两跳箭头路径，来源展开显示 JSON 位置，不显示虚构原文章节坐标。

## 类别含义与回答边界

文件混合了用途、科室和药理名称，也有疑似错误归类。例如西药文件在“抗生素药物 / 青霉素类”下包含“阿奇霉素分散片”。该事实只是数据质量问题线索，不能因为来自本地 JSON 就当作已经确认的医学分类。

独立分类图展示“本地文件将某制剂列在哪个分类下”，并说明尚未核验为权威药理分类。分类驱动的分步发现查询现在可以先用分类筛选候选，再核对具体药物独立的医疗原文边；分类关系不能代替相互作用证明或原文明确类别归属。纯分类查询及有界分类发现的来源展示无需 Chroma、云端改写、重排或回答模型；普通临床问题保留原检索审核路径。详见《分类驱动的分步图检索.md》。
