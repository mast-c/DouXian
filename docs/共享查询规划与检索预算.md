# 共享查询规划与检索预算

患者问题理解结果会生成一份共享计划，保存于 trace 的 `query_plan`。图检索和 Chroma 使用同一 `plan_id`。

例如“喷鼻喷剂好几天，仍鼻塞，今天鼻内疼”会规划：

1. 不良反应、注意事项与新不适相关的原文。
2. 症状未改善时的资料记载及时间条件。
3. 给药方法与使用注意事项。

计划只提出资料检索目标，不认定症状由药物导致，不换算“好几天”为某个确定天数。药名未确认时先澄清。

## 调用与时间预算

| 阶段 | 当前限制 |
| --- | --- |
| 患者查询规划 | 本地执行，0 次模型调用，最多 3 个目标；额外栏目合并保留 |
| Chroma + BM25 召回 | 最多 2 路并发，每目标最多 12 条；召回等待预算 12 秒 |
| 去重后精排 | 最多 36 条候选，最多调用 1 次；等待预算 10 秒 |
| 精排输入压缩 | 每候选最多发送 1200 字符，结果仍保留完整原文 |
| 召回与精排整体等待 | 最多 24 秒预算；不包括首次初始化、父级原文核验、补检、证据审核、回答生成 |
| 查询向量接口 | 8 秒传输超时；入库向量生成保持原路径 |
| 图路径检索 | 一次遍历，原有跳数/扩展数量限制加 3 秒遍历预算 |
| 原有 Qwen 分解兜底 | 仅不适用患者计划时使用，5 秒接口超时、禁用客户端重试，最多 3 条查询 |
| Neo4j 连接 | 5 秒连接/获取连接超时，关闭事务自动重试，避免服务未启动时反复等待 |

这里的预算不是整轮回答耗时承诺。Python 超时返回不能强行终止已经进入 SDK 的请求；后台线程数量有限制，迟到结果不参与当前回合。SDK 的传输超时与调用端等待预算共同限制等待。

## 失败和证据处理

部分召回失败时保留已成功返回的候选。精排异常/超时时按真实召回候选排序回退，并明确记录降级；不会新增原文、伪造精排分数或绕过 Neo4j 原文核验与 Evidence Guard。

图遍历达到时间预算时记录 `retrieval_timeout`，不能解释为不存在关系。图路径仍逐边核验原始来源；用法用量没有对应图关系时由文本通道检索，不制造图边。

共享关系目标通过一次有界遍历执行，并在 `semantic_graph.task_coverage` 记录关系覆盖。关系覆盖、候选覆盖都不是临床证据充分性的审核结果。多个药物仍保留整体连接约束，不会把两条独立单药资料当作已经证明合用影响。

## 查看诊断

- `query_plan.tasks`：检索目标、栏目、子查询。
- `semantic_graph.execution`：计划标识、遍历次数和遍历预算。
- `query_execution.graph`：同一份图遍历执行摘要，便于与 Chroma 对照。
- `semantic_graph.stats.time_budget_exhausted`：是否达到时间限制。
- `query_execution.chroma`：召回/精排调用数、阶段耗时、失败类型、降级状态。
- `query_execution.chroma.uncovered_tasks`：候选阶段未覆盖的目标。
- `query_execution.chroma.after_provenance_uncovered_tasks`：原文核验后仍未覆盖的目标。

这些诊断字段随单轮 trace 导出。实际云端耗时和召回质量需在项目运行环境测试；离线测试使用接口桩验证预算、调用次数和失败行为。

本轮本地图回放与离线调用统计见 `data/reports/shared_query_plan_replay_20261104.json`。无候选且发生召回超时时，文本工具返回 `retrieval_timeout`，避免把超时误报成库内不存在相关章节。
