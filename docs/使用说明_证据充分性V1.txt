豆馅 RAG / Evidence Sufficiency V1（证据充分性校验 + 拒答）
============================================================

适用范围
--------
仅接入 Streamlit 的“知识库”模式。联网模式、自动模式不改变。
不会重切 Chunk，也不会重新向量化。每次知识库请求会多调用一次 Qwen 做证据审核。

新增三个文件
------------
1) evidence_guard.py           校验模型输出、核查证据原文和编号、决定回答/部分拒答/拒答
2) install_evidence_guard.py   在你本机现有 rag.py 上安装补丁，保留原有提示词和其它修改
3) test_evidence_guard.py      7 组离线模拟测试，不调用 DashScope、Chroma、Embedding

安装方法（PowerShell，操作前先停止 Streamlit）
--------------------------------------------
1. 将 ZIP 解压到 rag.py 所在的 data 目录，确保四个文件处于同一目录。
2. 运行离线测试：
       python .\test_evidence_guard.py
3. 检查你的 rag.py 是否能自动增量安装：
       python .\install_evidence_guard.py --dry-run
4. 上一步通过后，正式安装：
       python .\install_evidence_guard.py
   会自动备份原版：rag.py.backup_年月日_时分秒
5. 运行语法检查：
       python -m py_compile .\rag.py .\evidence_guard.py
6. 重启前端：
       streamlit run .\豆馅.py

安装程序不会用提供的旧 rag.py 覆盖你当前的 rag.py。
若你的代码结构已发生变化，安装器找不到锚点时会停止、不写文件。
这种情况下，把你目前的 rag.py 发给助手做针对性适配，不要强行替换整份后端。

验证问题（选择“知识库模式”）
-------------------------
A. 正常有依据
   随机森林与 Bagging 有什么关系？随机森林有哪些优势？
   预期：正常回答，引用正确的 [1] 等证据。

B. 完全证据不足
   《机器学习》教材是否记载随机森林在2025年某国际竞赛中的准确率？给出数值。
   预期：返回“当前检索到的知识库证据不足”，不继续调用回答流。

C. 部分证据不足
   随机森林为什么改善泛化性能？教材有没有给出它在2025年某项国际竞赛的准确率？
   预期：解释有依据的部分；程序追加未支持部分的拒答说明。

D. 错误前提
   贝叶斯网为什么必须使用循环神经网络才能表达属性依赖？
   预期：使用 DAG 证据纠正错误前提；不编造因果关系。

终端还会打印：
   ========== 证据充分性校验 ========== answer / partial / refuse / error
trace 中会新增 evidence_coverage 字段，以备以后接入前端校验可视化。

决策语义
--------
answer  = 每个问题方面都有可以核实的引用（含被证据反驳、需要纠正的错误前提）。
partial = 部分有依据，只将已验证原文发给生成模型，后附程序确定的部分拒答。
refuse  = 当前检索证据无法支持任何必要方面，不调用回答模型。
error   = 审核模型失败、JSON 不合法等，暂停回答（失败关闭）。

设计限制（重要）
--------------
1. “充分性”由 Qwen 在单独的一次调用中判别；Python 会检查引文是否真实存在、
   引用编号是否有效，并按照结果阻止无依据回答。这不能保证模型的语义判断绝对正确。
2. 较严格的逐字引文检查可能会将真实可回答的数学表达/扫描文本误判为不足；
   这是偏向保守的 V1 行为。建议评测误拒答率。
3. 只覆盖知识库模式；自动模式中 Agent 自主调用知识库工具时，本补丁尚未接管。
4. 当前未实现回答生成之后逐条事实复核，后续 Self-RAG 再扩展。
5. 校验失败时会停止生成，因而可能增加一些校验 API 延迟和 Token 费用。

回滚
----
先停止 Streamlit。把自动生成的 rag.py.backup_* 文件复制回 rag.py，
然后重启 Streamlit。无需操作 chroma_db。
