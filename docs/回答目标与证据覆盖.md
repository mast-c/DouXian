# 回答目标与证据覆盖

患者问题理解与共享查询计划之外，增加“药品 × 资料栏目”的证据目标。它们用于检索覆盖与名额分配，不直接表示临床证据充分，也不会把辅助检索目标变成用户额外必答项。

## 两药成分问题

“阿司匹林肠溶片与布洛芬片的成分和相互作用”分别审核两种制剂的成分，以及两药相互作用原文。辅助检索的注意事项不自动加入必答清单。

明确药名、简单栏目查询且不超过五项时才固定审核清单；患者询问诊断、病因、能否自行用药、疗效、机制或产品未确认时，继续动态审核原始问题。

合并证据按目标覆盖优先，不再为每种检索来源固定分配一半名额。完整图路径保持完整，图路径内逐边核验的局部事实可以被引用；两条独立单药路径不作为两药相互作用证据。

原有成分字面查找机制仍限定于已逐边核验、同一来源制剂的成分原文。固定清单使审核模型遗漏成分时仍能检查这条已有事实；该机制不放行剂量、因果、诊断或合用安全性。相互作用、禁忌等字面提及仍需语义审核，来源技术核验不等于医学审核。

## 定向补检预算

已规划的药品问题只在审核为部分支持或拒答、并且相应目标没有资料候选时补检。已经有相关原文而缺少临床结论时，不重复搜索同一栏目。新证据仍可能无法回答，不能保证补检成功。

- 最多一个本地生成的补检查询，聚焦最多三个缺失目标，额外目标记入 deferred_target_ids。
- 不调用模型改写，不追加重排，不重新遍历图谱。
- 召回含原文核验等待预算六秒，最多加入三个经过父级原文核验的片段。
- 仅新增非重复证据时复审一次，等待预算八秒；真实客户端同步设置超时且禁用重试。
- 复审固定首轮完整清单，必须保留原有已支持方面；变差、异常或超时均保留首轮结果。

新增补检与复审最多约十四秒调用端等待，不包括首轮检索、首轮审核和最终回答生成。不能强制终止已进入 SDK 的请求；迟到结果不修改当前 trace，后台并发受到共享线程池限制。非药品、未形成目标计划的问题保留原有兜底补检路径，不适用这十四秒预算。

## trace 诊断

- query_execution.chroma.candidate_decisions：每条召回候选的药品/栏目筛选原因；selected_candidate_keys 表示合并精排后保留项。
- retrieval_summary.search_knowledge_base.medical_validation.decisions：父级核验、栏目筛选或名额限制的原因。
- evidence_flow.targets：资料目标和对应制剂检索范围。
- evidence_flow.stages / transitions：实体过滤、父章节去重、合并、补检、生成输入各阶段保留项和排除原因。稳定 key 不受引用编号变更影响。
- evidence_flow.initial_review / aspects：首轮与最终审核逐项结果、引文校验原因及成分字面查找标识。
- evidence_flow.answer：最终正文出现的候选引用编号，仅表示引用出现，不宣称每个目标都被正确回答。
- query_execution.source_gap：补检调用数、验证结果、超时及复审预算。

source_gap 中 candidate_new_chunks 为补回的非重复候选数，accepted_new_chunks 与 self_rag_retry.new_chunks 为复审后实际保留数；复审超时会单独记录 review_timed_out，不能将候选发现数误当成已采用数。

这些字段随单轮 JSON 导出。生成提示中逐项提供审核通过的问题、证据编号和原文引句，减少已有事实在生成时再次遗漏。
